## Antes de publicar após aprovação

1. Confirmar as variáveis públicas VITE_SUPABASE já existentes.
2. Confirmar a URL, a chave de servidor e a chave pública do mesmo Supabase no runtime do Vercel.
3. Configurar GITHUB_TOKEN, GITHUB_OWNER, GITHUB_REPO e GITHUB_BASE_BRANCH a partir do .env ignorado, preservando o destino do repositório de regras.
4. Sincronizar somente os arquivos de código, sem .env, .openai/, artifacts/ ou credenciais.
5. Publicar o commit aprovado e testar a rota de produção, o login e o status do GitHub. A criação real de PR depende de uma solicitação aprovada com evidência e permanece uma ação explícita do usuário.

Não há migração de banco neste conjunto. Testes de servidor verificam permissões, persistência de validação, exclusão e fluxo de exportação. Os testes de interface usam dados controlados em Playwright; a prévia da aplicação mantém a autenticação real.
